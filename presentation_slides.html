Slide 3 • Mathematical Foundations

Operating Principle of CRC: Modulo-2 Division

Discrete Math Slide 03 / 10
1. POLYNOMIAL MAPPING
Galois Field GF(2)
• Bitstream is treated as polynomial coefficients over GF(2).
• Example: 'A' = 01000001₂ ➔ \(P(x) = x^6 + 1\).
• Arithmetic Rule: Addition and subtraction are identical to bitwise XOR (⊕).
• No Carries/Borrows: Enables line-rate single-cycle hardware execution.
2. DIVISION & PADDING
32-Zero Appending
• Sender appends 32 zeros: \(M(x) \cdot x^{32}\).
• Long division performed with 33-bit Generator \(G(x)\).
• If leading bit is 1, XOR with divisor; if 0, shift 1 bit right.
• \(M(x) \cdot x^{32} = Q(x)G(x) \oplus R(x)\). Remainder \(R(x)\) is the 32-bit CRC.
3. SYNDROME PROOF
Receiver Zero Remainder
• Codeword Transmitted: \(T(x) = M(x) \cdot x^{32} \oplus R(x)\).
• \(T(x) = Q(x)G(x) \oplus R(x) \oplus R(x) = Q(x)G(x)\).
• Receiver calculates: \(T'(x) \pmod{G(x)} = R'(x)\).
• Decision Rule: If \(R'(x) == 0^{32}\) ➔ ACCEPT (No Error); else REJECT.

HANDWRITTEN PYTHON LOGIC
Core Functions (No zlib)
def ascii2binary(text):
  return ''.join(f'{ord(c):08b}' for c in text)

def xordiv(dividend, divisor):
  d, m = list(dividend), len(divisor) # 33 bits
  for i in range(len(d) - m + 1):
    if d[i] == '1':
      for j in range(m):
        d[i+j] = '1' if d[i+j] != divisor[j] else '0'
  return ''.join(d[-(m-1):]) # Last 32 bits

def compute_crc(text):
  return xordiv(ascii2binary(text) + '0'*32, get_divisor())

Modulo-2 Long Division Integer division propagates carries, producing arithmetic quotient. Built handwritten bitwise XOR loop shifting without carries/borrows. Mastered Galois Field GF(2) long division algorithms.
Divisor Synchronization Sender & receiver generated different random polynomials. Created singleton get_divisor() fixed for entire session in memory. Learned session-level state management and protocol parity.
Single-Screen Layout Long step outputs created ugly outer window scrolling. Engineered 2-row CSS grid with internal 6px custom scrollbars. Mastered responsive viewport budgeting without layout thrashing.

Slide 9 • Important Questions (Guideline Sec 12 & 13)

Viva Voce & Technical Defense Preparation

Viva Q&A Slide 09 / 10
MATHEMATICAL CONCEPTS
Concept Defense
• Q: What is CRC & why used?
Cyclic Redundancy Check; detects burst errors using polynomial long division over GF(2).

• Q: Why 33-bit divisor for 32-bit CRC?
A degree-32 polynomial has 33 coefficients. Dividing by degree-32 strictly leaves a remainder of degree ≤ 31 (32 bits).

• Q: Why is XOR used instead of subtraction?
In GF(2), addition and subtraction are identical to bitwise XOR with no carries or borrows.

• Q: Can CRC correct errors?
CRC is strictly for error detection. Error correction requires FEC (e.g. Reed-Solomon).
IMPLEMENTATION & VERIFICATION
Code & Verification Defense
• Q: How is text converted before CRC?
Each character is converted to 8-bit ASCII binary via ascii2binary() and concatenated.

• Q: How does the receiver detect an error?
Codeword \(T'(x) = ext{Data} + ext{Received CRC}\) is divided by \(G(x)\). If remainder is \(0^{32}\) ➔ ACCEPT; else REJECT.

• Q: What happens if one bit is changed?
The polynomial \(M'(x)\) differs from \(M(x)\), resulting in a non-zero syndrome remainder \(R'(x) eq 0\).

• Q: What error types are 100% detected?
All single-bit errors, all double-bit errors, and all burst errors ≤ 32 bits.

Chapter 1 — Introduction to Cyclic Redundancy Check (CRC)

1.1 Introduction to Error Detection

In industrial computing, operating systems, and networked telemetry systems, data is transmitted across physical media such as serial lines (RS-485, RS-232), Controller Area Networks (CAN bus), and Ethernet (Modbus TCP). These physical channels are inherently noisy and susceptible to thermal noise, electromagnetic interference (EMI) from heavy machinery, ground potential shifts, and signal attenuation. Consequently, bit flips occur during transit. Error detection is the operational mechanism by which redundant bits are appended to a raw data stream, enabling the receiving node to identify whether the received bitstream is identical to the transmitted bitstream before triggering physical actuation or committing audit logs.

1.2 Need for CRC

Traditional error-detection methods include single-bit parity checks and additive checksums (such as the 16-bit Internet Checksum used in IPv4). While computationally lightweight, these methods exhibit severe blind spots in industrial telemetry:

  • Parity Checks: Only detect an odd number of bit errors. Any even number of flipped bits (e.g., 2, 4, or 6 bits) entirely cancels out, resulting in a 50% failure rate for multi-bit noise bursts.
  • Additive Checksums: Treat data as integer words and compute arithmetic sums. Because addition is commutative ($A + B = B + A$), transposition errors (swapped bytes), zero-byte injections, and compensating bit errors go undetected.

Cyclic Redundancy Check (CRC) solves these vulnerabilities by treating the data bitstream as polynomial coefficients over Galois Field $GF(2)$. Because polynomial division is non-commutative and spreads bits through long division, CRC guarantees 100% detection of all single-bit errors, all double-bit errors, all odd-count bit errors, and all burst errors with lengths up to the degree of the generator polynomial.

1.3 Basic Working of CRC

The CRC algorithm operates symmetrically across sender and receiver using a predefined generator polynomial $G(x)$ of degree $n$ (consisting of $n+1$ bits):

  1. Sender Side: The message $M$ of $k$ bits is represented as polynomial $M(x)$. The sender multiplies $M(x)$ by $x^n$ (appending $n$ zeros). It divides $M(x) \cdot x^n$ by $G(x)$ using Modulo-2 division, obtaining an $n$-bit remainder $R(x)$. The transmitted codeword is $T(x) = M(x) \cdot x^n \oplus R(x)$.
  2. Receiver Side: The receiver receives $T'(x)$ and divides it by the identical generator $G(x)$. If $T'(x)$ is undamaged, $T'(x) \pmod{G(x)} \equiv 0$. If remainder $R'(x) eq 0$, data corruption or unauthorized tampering is detected.

1.4 Applications of CRC

Due to its hardware-deterministic performance and high detection rate, CRC is the global standard in mission-critical protocols: Ethernet IEEE 802.3 (CRC-32), SATA/NVMe storage controllers, USB (CRC-5 and CRC-16), CAN Bus in automotive/robotics (CRC-15), ZIP/PNG file formats (CRC-32), and SCADA industrial telemetry gateways.

1.5 Problem Statement and Product Requirements

Problem: Industrial SCADA logs contain critical time-series telemetry (e.g., turbine RPM, valve pressure, motor current). In-flight noise or malicious manipulation can alter telemetry values, inducing catastrophic mechanical failure or false shutdowns. Standard student implementations rely on black-box C libraries (such as zlib.crc32), obscuring internal mechanics during academic evaluation.

Chapter 2 — Mathematical Principles of CRC

2.1 Binary Data and Polynomial Representation

In algebraic coding theory, any $k$-bit binary stream $b_{k-1}b_{k-2}\dots b_1 b_0$ is mapped directly into an algebraic polynomial $P(x)$ whose coefficients belong to the Galois Field of two elements, $GF(2) = \{0, 1\}$: $$P(x) = b_{k-1}x^{k-1} + b_{k-2}x^{k-2} + \dots + b_1 x^1 + b_0 x^0$$ For example, the ASCII character 'A' has binary value $01000001_2$, which corresponds to the polynomial $P(x) = x^6 + 1$. The character 'B' ($01000010_2$) corresponds to $x^6 + x^1$.

2.2 Generator Polynomial

The generator polynomial $G(x)$ determines the algebraic strength and degree of the CRC code. To generate an $n$-bit CRC remainder, $G(x)$ must be of degree $n$, which requires exactly $n+1$ bits. For CRC-32, $n=32$, necessitating a 33-bit divisor. Crucially, the Most Significant Bit (MSB, coefficient of $x^{32}$) and the Least Significant Bit (LSB, coefficient of $x^0$) must strictly be 1. The MSB ensures that the divisor degree is exactly 32. The LSB ($x^0 = 1$) ensures that $G(x)$ is not divisible by $x$, guaranteeing the detection of all trailing zero shifts and synchronisation slips.

2.3 Modulo-2 Division

Modulo-2 division is identical to binary long division with one fundamental distinction: addition and subtraction are performed without carries or borrows. In regular integer division, subtracting a larger number borrows from adjacent bits. In $GF(2)$, subtraction is identical to addition, which is implemented as a bitwise XOR operation ($\oplus$). At each division step, if the leading bit of the working dividend is 1, the divisor is XORed with the current window; if the leading bit is 0, the window is shifted by one bit.

2.4 XOR Operation

The truth table for Exclusive-OR ($\oplus$) is: $0 \oplus 0 = 0$, $0 \oplus 1 = 1$, $1 \oplus 0 = 1$, and $1 \oplus 1 = 0$. In $GF(2)$, $A \oplus B = A + B = A - B$. A critical identity for CRC verification is self-cancellation: $A \oplus A = 0$.

2.5 CRC Remainder and Codeword Generation

The message polynomial $M(x)$ is pre-multiplied by $x^{32}$ (shifting it 32 bits left, equivalent to appending 32 zeros). Dividing $M(x) \cdot x^{32}$ by $G(x)$ yields quotient $Q(x)$ and remainder $R(x)$: $$M(x) \cdot x^{32} = Q(x) \cdot G(x) \oplus R(x), \quad ext{where } \deg(R(x)) < 32$$ The transmitted codeword $T(x)$ is formed by replacing the 32 zero bits with $R(x)$: $$T(x) = M(x) \cdot x^{32} \oplus R(x)$$

2.6 CRC Verification and Error Detection

When the receiver evaluates the transmitted codeword $T(x)$, it divides by the identical polynomial $G(x)$: $$T(x) = Q(x) \cdot G(x) \oplus R(x) \oplus R(x) = Q(x) \cdot G(x) \implies T(x) \pmod{G(x)} \equiv 0$$ If noise flips bits during transmission, the received message is $T'(x) = T(x) \oplus E(x)$, where $E(x)$ is the error polynomial. When the receiver computes the remainder: $$T'(x) \pmod{G(x)} = [T(x) \oplus E(x)] \pmod{G(x)} = 0 \oplus [E(x) \pmod{G(x)}] = E(x) \pmod{G(x)}$$ An error escapes detection if and only if $E(x)$ is an exact multiple of $G(x)$. For a 32-bit random polynomial, the probability of an undetected burst is bounded by $2^{-32} pprox 2.328 imes 10^{-10}$ (less than 1 in 4.29 billion).

3.10 Error Introduction and Detection Mechanics

To validate error detection, an adversarial harness was built into the verification endpoint. When the log [TURBINE_01] RPM:3450 is corrupted by flipping bit 0 of character '0' to '1' (ASCII 48 to 49, yielding RPM:3451), the codeword bitstream alters from $T(x)$ to $T(x) \oplus x^k$. Because $G(x)$ does not divide $x^k$, xordiv() returns a non-zero remainder, immediately triggering the REJECT state. 

def xordiv(dividend: str, divisor: str) -> str:
    d, m = list(dividend), len(divisor)  # m = 33
    for i in range(len(d) - m + 1):
        if d[i] == "1":
            for j in range(m):
                d[i + j] = "1" if d[i + j] != divisor[j] else "0"
    return "".join(d[-(m - 1):])  # Strictly returns the last 32 bits as remainder

Appendix A — Complete Python Source Code

Verbatim implementation of core mathematical engine (backend/crc_checker.py): 

import random

GENERATOR = None

def generate_divisor() -> str:
    middle = "".join(random.choice("01") for _ in range(31))
    return "1" + middle + "1"  # 33 bits, degree 32

def get_divisor() -> str:
    global GENERATOR
    if GENERATOR is None:
        GENERATOR = generate_divisor()
    return GENERATOR

def ascii2binary(text: str) -> str:
    return "".join(f"{ord(ch):08b}" for ch in text)

def binary_to_hex(binary_str: str) -> str:
    num = int(binary_str, 2)
    return format(num, f"0{(len(binary_str)+3)//4}X")

def xordiv(dividend: str, divisor: str) -> str:
    d = list(dividend)
    m = len(divisor)
    for i in range(len(d) - m + 1):
        if d[i] == "1":
            for j in range(m):
                d[i + j] = "1" if d[i + j] != divisor[j] else "0"
    return "".join(d[-(m - 1):])  # Last 32 bits = remainder

def compute_crc(text: str) -> dict:
    divisor = get_divisor()
    binary_data = ascii2binary(text)
    padded_data = binary_data + ("0" * (len(divisor) - 1))
    remainder = xordiv(padded_data, divisor)
    return {"crc": remainder, "divisor": divisor, "hex": binary_to_hex(remainder)}

def verify(text: str, received_crc: str) -> dict:
    divisor = get_divisor()
    binary_data = ascii2binary(text)
    codeword = binary_data + received_crc.strip()
    remainder = xordiv(codeword, divisor)
    return {"accepted": remainder == ("0" * (len(divisor) - 1)), "remainder": remainder}
